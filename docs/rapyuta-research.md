# Rapyuta ASRS — 조사 요약과 모델링 가정

## 실제 시스템 (공개 자료)

| 항목 | 내용 | 출처 |
|---|---|---|
| 회사 | Rapyuta Robotics (도쿄). 개발은 NEDO 지원 | [S2] |
| 구조 | 바닥 블록 + 기둥 + 바닥 패널을 쌓는 다층 선반. 층마다 로봇이 빈 아래를 달림. 7층 이상 | [S1] |
| 기둥 | 층마다 630 mm 기둥 (작은 물건용 530 mm 짧은 기둥). 유리섬유 강화 플라스틱(GFRP), 나사·볼트 없이 손으로 조립 | [S1], [S6] |
| 바닥 | 앵커가 필요 없음, 면진 받침. 3D 진동대 시험. 기둥·보 주변, 임대 건물, 위층, 메자닌에도 설치 가능 | [S1], [S3] |
| 로봇 | 높이 80 mm "업계에서 가장 얇은 로봇". 메카넘 휠로 멈추지 않고 방향 전환. 배터리 구동 | [S1], [S2], [S6] |
| 속도 | 최고 2.5 m/s (이미지 설명에는 2.4 m/s로 적힌 곳도 있음) | [S1], [S3] |
| 빈 꺼내기 | 로봇이 다른 빈 밑을 지나 목표 빈 아래로 가서 들어 올림. 빈을 여러 줄로 촘촘히 두고, 안쪽 빈은 앞쪽 빈을 잠시 옮긴 뒤 꺼냄 | [S1] |
| 빈 | W65 × D44 cm, 높이 22 / 40 / 58 cm 세 종류. 칸막이 추가 가능 | [S1] |
| 리프트 | 고속 리프트로 로봇이 층을 이동. 단순한 체인 구동, 어느 위치에나 설치 가능 | [S1], [S6] |
| 피킹 스테이션 | 작업자 한 명 주위에 빈 최대 8개. 디스플레이, 프로젝터, 모션 캡처 카메라 2대로 안내. 잘못 집으면 경고음과 빨간 불, 완료 버튼이 반응하지 않음 | [S1], [S3] |
| 로봇 수 | 스테이션 1개당 로봇 약 20대 기준으로 설계. 제어 시스템은 로봇 300대까지 검증 | [S6], [S1] |
| 충전 | 자동 배터리 교환 1분 이내 (전원 유지). 완충 시 약 3시간 주행, 24시간 운영 | [S1], [S6] |
| 주장 | 생산성 10배, 보관 효율 2.5배 (비교 기준은 밝히지 않음) | [S2], [S3] |
| 기타 | 출고 빈 분류·순차 출고 기본, 무료 WMS·API, 출고 빈 위치를 출고 빈도로 정함 | [S1], [S3] |
| 고객·수상 | alps logistics, Nippan (사용 후기). 2024 굿디자인 금상 | [S2] |

**외관** (공식 사진 확인): 빨간 기둥, 흰 격자선이 그려진 검은 바닥 패널, 흰 빈, 검은 납작한 로봇. 글로 적힌 색 정보는 없습니다.

**공개 자료에 없는 것**: 셀 피치, 통로 배치, 로봇 가로·세로 치수와 무게, 가속도, 들어 올리는 높이, 리프트 속도, 피킹 시간. 아래 값은 사진과 위 수치로 잡은 **가정**입니다.

## 이 모델의 가정

| 항목 | 값 | 비고 |
|---|---|---|
| 그리드 | 16 × 13 셀, 셀 0.70 × 0.50 m (11.2 × 6.5 m), 7층 | 셀 = 빈 650 × 440 mm + 여유 |
| 층 높이 | 0.63 m (공식 기둥 길이), 맨 아래 패널 0.12 m | 빈 400 mm 높이 사용 |
| 빈 받침 | 격자 교차점마다 높이 0.10 m 다리. 로봇(80 mm)이 빈 밑을 지나감 | 가정 |
| 기둥 | 격자선 2칸마다 45 mm 각 빨간 기둥 | 가정 |
| 통로 | 6행마다 통로 행 (y = 0, 6, 12), 좌우 끝 2열씩 통로. 빈을 실은 로봇은 빈 없는 셀만 다님 | 각 셀 깊이 최대 2칸 |
| 일방통행 | 빈을 실은 로봇: 통로 행은 행마다 +x/−x 번갈아, 좌우 2열은 바깥·안쪽 반대 방향 | 정면 충돌 방지 |
| 앞쪽 빈 치우기 | 목표 빈까지 0-1 BFS로 가장 적게 옮기는 경로를 찾고, 막는 빈을 가까운 빈 셀로 옮김 | |
| 로봇 | 20대, 0.56 × 0.36 × 0.08 m, 2.5 m/s, 1.2 m/s², 방향 전환 0.25 s, 들기·내리기 0.9 s | 속도·높이만 공식 |
| 리프트 | 5대 (왼쪽 3, 오른쪽 2), 1.6 m/s, 1.6 m/s², 정지 0.4 s. 한 번에 로봇 1대 | 가정 |
| 피킹 스테이션 | 2개 × 슬롯 4개, 2층 앞쪽 (작업자는 바닥에 서고 빈은 허리 높이). 피킹 5~10 s | 가정 |
| 빈 | 633개 (보관 셀의 78%), 층마다 빈 셀 12개 이상 유지 | |
| 주문 | 시간당 600건, 상위 20% 빈이 수요의 80%. 인기 빈은 낮은 층·통로 가까이에 처음 배치 | |

## 시뮬레이션 결과 (1시간, 1/60 s 스텝, seed 1~3 평균)

| 로봇 수 | 처리량 (빈/h) | 로봇당 (빈/h) | 로봇 가동률 | 막혀 기다린 시간 | 스테이션 작업자 가동률 | 앞쪽 빈 치우기 / 출고 | 리프트 운행 / h |
|---|---|---|---|---|---|---|---|
| 10 | 321 | 32 | 98% | 12% | 33% | 0.21 | 1,560 |
| **20 (기본)** | **431** | **22** | **69%** | **12%** | **45%** | **0.19** | **1,590** |
| 30 | 451 | 15 | 47% | 7% | 47% | 0.18 | 1,450 |

- 10대에서는 로봇이 거의 쉬지 않아(98%) 로봇 수가 상한입니다. 20대부터는 로봇이 남는데도 처리량이 시간당 430~450 빈에서 멈춥니다. 슬롯 8개가 "빈이 오는 중"으로 예약된 채 로봇 이동(리프트 대기 포함)을 기다리는 시간이 길어, 작업자는 절반 이상 기다립니다. 실제 시스템이 스테이션마다 로봇 약 20대를 두고 빈 여러 개를 동시에 준비하는 이유와 같은 구조입니다. 처리량을 더 올리려면 스테이션·슬롯이나 리프트를 늘려야 합니다.
- 앞쪽 빈 치우기는 출고 1건당 약 0.2회입니다. 인기 빈을 처음부터 낮은 층·통로 가까이에 두기 때문입니다.
- 리프트 5대가 시간당 약 1,600회(대당 약 320회) 움직여, 층 이동이 많은 구조라는 점이 드러납니다.

## 같은 로직의 세 가지 구현

- `web/rapyuta-sim-core.js` — 기준 구현 (Node/브라우저)
- `tools/export_rapyuta_trace.js` — 600초 워밍업 후 30초를 30fps로 기록 (1/60 s 스텝) → `blender/rapyuta_trace.json`
- `Assets/Rapyuta/Scripts/RapyutaSim.cs` — Unity C# 포팅. 같은 mulberry32 난수 사용. seed 1~3에서 10분 단위 처리 건수가 JS와 정확히 같음 (mono로 확인)

## 30초 영상 동선 (seed 3, warmup 600 s)

| 시간 | 장면 |
|---|---|
| 0~4 s | 앞 오른쪽 위에서 전체 |
| 4~10 s | 피킹 스테이션: 빈 4개, 디스플레이, 완료 버튼, 프로젝터 빛 |
| 11~16 s | 왼쪽 리프트: 로봇 한 대가 2층에서 리프트를 타고 5층으로 올라감 |
| 16~24 s | 층 사이 통로를 로봇 높이로 따라감 (양옆은 빈, 위는 위층 패널) |
| 24~28 s | 오른쪽 리프트 사이로 나와, 로봇이 앞쪽 빈을 들어 옆으로 옮기는 장면 (26 s) |
| 28~30 s | 빠지며 전경 |
